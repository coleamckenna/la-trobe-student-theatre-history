Contributing to the archive¶

Each production page is a curated historical record, not a comment thread. Corrections and debate happen on GitHub so changes stay auditable and can be merged back into the catalogue.

Edit this page¶

Production wiki pages are generated from source files under productions/. Use Edit this page on any production entry to open the canonical production.md on GitHub and propose a pull request.

Typical pull request changes:

  • Fix typos or formatting
  • Add or correct dates, venues, and credits
  • Add citations in Notes or Materials
  • Link to programs, reviews, or photos hosted elsewhere (see content notice)
  • Optional Media section for URLs that should display inline on the wiki (see data guide)

The build turns supported URLs in Materials, Notes, and Media into embeds that load from the original host — nothing is copied into the repo. Use stable archive links where possible.

Do not edit files under docs/productions/ or docs/categories/ — they are regenerated by python3 scripts/build_wiki.py.

Discuss this page¶

Use Discuss this page to open a GitHub Discussion about one production without editing the record yet. That is the right place for:

  • Disputed dates or seasons
  • Cast and crew recollections
  • Missing production photographs
  • Conflicting archival sources
  • Oral history from former students and staff

When evidence is clear, someone updates production.md via pull request. The discussion thread remains as provenance.

Discussions use the General category (see wiki.toml). The same category powers the Giscus embed on production pages.

Pinning a discussion to a page¶

Pre-filled “new discussion” links are used until a thread exists. To link a stable thread number, add an entry to discussions-map.toml at the repo root:

["productions/2017/03/the-light-within-a-night-2017/production.md"]
discussion = 42

Rebuild the wiki after updating the map.

Contribute material¶

Programs, photographs, and scans are generally not committed to this repository because of copyright. Instead:

  • Open a GitHub issue describing what you have (with your repo URL from wiki.toml once configured), or
  • Post in the relevant Discuss this page thread with links or descriptions of where material can be accessed

Maintainers can then cite external holdings in Materials or Notes.

Giscus on production pages¶

Each production entry shows a Giscus thread below the contribution footer (same General category, pathname mapping). Configuration is in docs/javascripts/giscus.js and wiki.toml ([giscus]). Discuss this page opens the thread on GitHub; the embed shows it inline. Catalogue updates still go through pull requests on production.md.
